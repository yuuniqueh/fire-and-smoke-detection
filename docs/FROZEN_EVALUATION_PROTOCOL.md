## 分组依据与范围

通过原视频两处抽帧检查视觉相似线索，增加 ORB 特征与 RANSAC 几何匹配核查，排除顶部覆盖文字作为主要匹配依据。fire `posVideo7.876.avi` / smoke `testpos03.819.avi` 有 268 个匹配内点，覆盖较小图约 49.5%；烟雾 `testpos06.822.avi` / `testpos07.823.avi` 有 22 个内点，覆盖约 36.4%。这支持同场景的保守处理，不证明原始采集来源。

全部 9 个已有视觉/来源候选组与上述匹配约束均按“不能跨两侧”处理，传递关联也合并。相同水印、相似场地但尚不能确认同一拍摄的视频，宁可放在同一侧。未建立联系的视频采用单文件约束组，不声称这些组一定相互独立。证据保存在 `outputs/firesense-similarity.json` 和冻结计划中。

本轮因此是**固定保守分组下的初步内部对照**。原始来源和与模型训练数据的重叠没有查清，不报告完全独立外部测试准确率，也不替代真实部署验证。此前指南中“同源核查后进行正式评价”的条件仍适用于正式独立效果结论；当前不写入用户标注里的 `group_verified`，也不把机器相似性检查当作来源证明。

## 对照方法

- 单帧状态：当前帧任意一个该类检测框，置信度阈值 0.35。
- 时序状态：当前帧任意一个该类已确认轨迹，包括短暂漏检时仍保持的确认状态。
- 两种方法共用同一份检测输出；不重复运行模型制造不同输入。模型为已登记的 D-Fire 微调权重，输入尺寸 640，时序参数沿用已冻结的默认配置。
- 完整读取每个纳入视频的全部帧，按帧号/FPS记录时间；保存逐帧检测、时序、事件及统计，不额外编码结果 MP4。工程测速会因省略绘图/视频写入不同于桌面版，不用于宣称桌面端到端速度。
- 原四段开发日志仅在来源、模型、阈值和配置相同时复用，时序状态用当前冻结代码重新回放。其余 40 段运行模型一次。
- 不调整风险参数，也不把风险等级当作火灾真假或真实危险程度标签。

## 指标

fire、smoke 分别评价。不确定状态排除该文件的该类指标；烟雾不确定不影响确定的 fire 指标。

可见区间与活动状态分别按 ≤1 秒间隔合并成场景片段，两种方法使用同一规则。某类真值场景事件只有在实际标注可见的帧上存在相应活动提示才计检出；仅在合并间隔中有提示不能计检出。其余事件计漏提示。

负标签帧上的活动提示按同一合并规则计“误提示片段”，同时保留逐帧错提示数和原始确认通知数。误提示片段不是弹出通知次数。每负分钟误提示率 = 所有误提示片段数 / 所有负标签时长分钟，不能简单平均各视频的率。

首次有效活动提示时间减去对应真值场景起点得到延迟，只对已检出事件平均；报告必须同时展示漏提示数量。片段从首帧已有目标时，起点为片段开始，不是实际点火。已有活动状态持续进入真值正区间时可能零延迟，须结合误提示数据解释。

真值只有类别与时间，没有全量框标注；时间匹配不能证明框落在正确目标上，不报告定位 mAP。没有正事件时事件检出率留空，没有负标签时长时误提示率留空。

## 复现与后续修改

```powershell
.\.venv-pytorch\Scripts\python.exe -X utf8 experiments/freeze_firesense_plan.py
.\.venv-pytorch\Scripts\python.exe -X utf8 experiments/benchmark_firesense.py
```

第一条在计划已存在时保留原计划，不能静默重抽有利划分。第二条生成独立 `outputs/benchmark-v1-*` 目录。如果中断，传 `--output` 和该目录完整路径恢复；程序核查计划、源码版本、输入视频和已完成日志哈希。

后续机制修改根据开发组失败案例提出，再冻结新版本检查内部留出；不按留出逐段选择阈值或删差例。重复使用同一留出会削弱未见过数据的评价性质，后续需保留新增素材检验。

原视频与用户标注保留；实验不把所有视频切成帧并混洗，不自动生成训练标签，不开始训练模型。
