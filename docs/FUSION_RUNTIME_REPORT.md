# 可切换亮光融合模式：软件运行验证

日期：2026-10-09。已将“候选 fire 0.35 + 原 smoke 0.35”接入命令行和桌面，保留原模型为默认和对照。此接入复现了既有开发结果，没有消除其覆盖下降和部分确认延迟问题。采用分析见 `MODEL_REPLACEMENT_DECISION.md`。

## 已完成的检查

- `core/model_profiles.py` 统一选择检测器，原 `core/detector.py`、时序、评价及标注保持不变。候选运行前核验两个权重的 SHA256；缺失或版本不符明确报错，不静默换模型。
- 实际运行新增软件适配器，完成全部 30 段开发视频、28,611 帧：每帧输出与探索性融合回放完全一致，逐视频两类指标亦一致。结果保持 fire 9/13、确认误提示 0 段；smoke 9/11、确认误提示 1 段。
- 同次热身后的双模型预测适配器约 **81.5 帧/秒**，包含两次推理及传输、后处理，不包含解码、绘制、界面、导出和时序。不能当作软件实际播放帧率，也没有与原模型同次计时。
- 真实 Qt 后台在完整车灯视频 155 帧、喷射火焰视频 363 帧上运行；桌面保存的每帧检测与上项实际运行完全一致。前者无 fire 确认，后者产生正确 fire 事件；结果和 ZIP 导出保存了所选模式及两个模型的来源/版本/哈希。分析中锁定设置、结束后恢复；候选阈值固定为 0.35。
- 上述两段桌面不按原速等待，包含模型初始化、解码、绘制、保存的处理速度分别约 23.5 和 34.5 帧/秒。它们是短视频工程检查，不是长视频稳定性能保证。
- CPU 上限 80 帧的车灯视频链路完成，无已确认事件；包含初始化、解码、绘制及保存约 7.13 帧/秒。不代表 CPU 已满足实时要求，未完成长视频或跨机器测试。
- 87 项单元测试通过，新增检查覆盖类别编号冲突、其他类不进入火情、固定阈值、原检测器选项保持，以及模型缺失/篡改时拒绝运行。
- 原模型默认路径另完成 10 项桌面回归检查：完整分析、停止、重启、异常输入、历史查看、ZIP 导出和关闭清理均通过；分析时界面心跳最大间隔约 0.113 秒。

## 使用

桌面启动后，在“检测方案”选择“减少反光误报（候选）”；说明直接展示“部分火焰可能确认更迟或中断”。可在下一次分析前切回“原模型”，不是运行中改变同一份结果的模型。

命令行使用 `--model-profile brightlight`，固定阈值 0.35；`--model-profile original` 使用原方案。所需权重通过 `experiments/screen_brightlight_candidate.py --stage fetch` 按固定版本下载；软件启动时不自动联网下载。
