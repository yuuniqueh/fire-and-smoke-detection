# FIRESENSE 首轮固定内部划分评估

2026-10-06 已完成 44 段视频、36,461 帧的完整处理。开发 30 段，内部留出 14 段，5 段解码异常排除；烟雾不确定的一段仅排除 smoke 指标。划分、标注、模型和参数在未曝光素材推理前冻结。

分组采用视觉/来源线索的保守约束，原始采集来源和与模型训练素材的重叠尚未查清。因此这是小样本内部初评，不是完全独立的外部测试、定位准确率或真实风险判定准确率。

## 主要结果

| 分组 / 类别 | 场景事件检出：单帧 → 时序 | 漏提示：单帧 → 时序 | 负标签误提示片段：单帧 → 时序 |
|---|---|---|---|
| 开发 / fire | 11/13 → 8/13 | 2 → 5 | 52 → 3 |
| 开发 / smoke | 10/11 → 9/11 | 1 → 2 | 67 → 1 |
| 内部留出 / fire | 5/5 → 3/5 | 0 → 2 | 4 → 0 |
| 内部留出 / smoke | 4/5 → 2/5 | 1 → 3 | 5 → 0 |

时序机制减少了本批素材的误提示片段，同时增加漏提示和首次活动提示延迟，当前取舍不够理想。留出中没有观察到误提示不能推出未来误提示率为零；事件数也很少，不能把比例当成可靠的总体准确率。

误提示片段按负标签帧上的活动提示，以 ≤1 秒间隔统一合并；不是原始通知次数。场景事件检出只要求某一实际可见帧有该类活动状态，无法证明框定位正确。时序暂缺证据时的确认保持也被计入活动状态。

各方法已检出事件的平均延迟见完整报告。由于两种方法的检出数量不同，延迟均值的样本集合也不同，不能把均值差直接当作每个事件的额外等待时间。应与漏提示数量一起阅读。

## 开发组失败复核

开发组共 7 个时序漏提示的类别场景事件：

- 3 个在当前置信度 0.35 下没有任何对应类别的原始检测：`posVideo3.872.avi / smoke`、`testpos04.820.avi` 的一段 fire、`testpos06.822.avi / fire`。仅修改时序后处理无法恢复没有输入的检测。
- 4 个有少量或间歇性检测，但没有确认状态。其中 `testpos02.818.avi / fire` 有 145 个检测帧，分散在 23 个候选 ID 中，最大单轨迹正证据仅 0.734 秒；需复核框变化、间歇输出和区域关联，尚未确定主因。
- 其余几个新增漏提示仅有 1、2 或 3 个原始正检测帧。直接允许单帧确认会与减少误提示的目标冲突，需要先核查原图和标注，再设计有依据的机制。

上述是开发日志观察，不自动修改人工标签，也不把来源或关联问题宣布为已证实。内部留出失败案例不用于逐片调参。

下一步先复核这些开发片段与框变化，区分模型无输出、间歇检测和关联不稳定，再选择一项增强并冻结新版本验证。保留本轮全部失败结果与默认配置，不只展示成功片段。
