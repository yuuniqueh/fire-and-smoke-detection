# 时序事件确认机制

本模块将检测结果转为持续视觉事件，属于空间关联、时间窗统计和状态机的工程实现。不能仅凭采用这些常规方法就认定具有显著算法创新；效果与差异化需要独立实验支持。

## 数据与状态

每帧输入视频时间戳、原始检测类别/置信度/坐标以及帧宽高。时间采用视频帧序号/FPS，当前支持恒定帧率视频；摄像头与可变帧率视频接入时另用可信时间戳。

同类别相邻检测框先归并成候选区域，坐标归一化后按 IoU 做一对一关联。不同类别独立计数，远离的图像区域不能共用证据。

状态：待确认 -> 已确认 -> 关闭。待确认候选没有足够证据且超时后丢弃；已确认事件允许短时漏检，超时后关闭。输入停止或视频结束会关闭软件记录，但不声称真实火情已经结束。

## 默认参数

| 参数 | 默认值 | 含义 |
|---|---:|---|
| window_s | 1.5 秒 | 最近观察窗口 |
| min_observation_s | 1.0 秒 | 候选至少被观察这么久 |
| min_positive_s | 0.8 秒 | 窗口内正检测至少覆盖这么久 |
| min_presence_ratio | 0.7 | 正检测时间/有效观察时间达到此比例 |
| max_gap_s | 0.6 秒 | 与最近一次匹配检测间隔超过此值则关闭 |
| match_iou | 0.1 | 同类别区域匹配的最小 IoU |
| cluster_padding | 0.025 | 候选框归并时每侧的归一化扩展量 |
| cooldown_s | 2.0 秒 | 同类别、同区域上一次提示后的重复提示冷却 |

参数来自初始工程设计，尚未通过独立真实测试集调优。调整会改变误报、漏报和确认延迟之间的取舍，不将这些数值描述为最优值。

配置位于 configs/temporal.json；每次运行保存配置副本，便于复现。

## 时间统计

在相邻采样间隔内，使用前一次是否匹配检测的状态作零阶保持，累加有检测支持的时间。窗口最左侧可以保留跨边界的一次观测，用于准确裁剪区间。首次观测没有持续时间，不能立即确认。

确认同时要求当前帧匹配、观察时长达到 1 秒、正检测时间达到 0.8 秒、正检测时间比例达到 70%。采样间隔大于允许缺失间隔时重建候选，避免把未采样的长空档当成持续证据。

presence 是该区域的时间一致性比例，不是模型置信度，也不是火灾概率。区域检测置信度仍显示在原始模型框上。

## 提示与记录

确认转换时只产生一次视觉/控制台提示。短时漏检恢复仍是原事件。新事件处于同区域提示冷却期时，仍保存确认事件，但不产生重复提示；警示抑制状态记录在 alert_emitted 字段中。当前没有声音、短信或其他外部通知。

events.json 保存确认时间、确认延迟、最后检测时间、软件关闭时间、关闭原因及确认依据；temporal.jsonl 保存每帧区域状态与转换。未确认候选的开始/丢弃转换也保留。确认事件中 observed_span_s 是从首次候选到最后观察的时间跨度，可能含短时缺失，不能当作物理火焰连续燃烧时长。

## 能力限制

- 持续误检仍可能确认，屏幕播放火焰也可能确认；时间一致性无法自行鉴别物理真伪。
- 相邻的不同火源可能被归并，快速移动或明显框抖动可能造成事件断开；当前面向固定视角原型，不是完整多目标跟踪器。
- 延迟确认会抑制短事件，存在漏掉短时真实目标的可能。
- 同区域提示冷却可能抑制新的独立事件提示，故事件记录保留，并在配置及实验中报告。
- 帧数元信息与实际解码不一致时保留已有提示；不能将软件读取完成等同于素材绝对完整。

## 可复现检查

```powershell
.\.venv-pytorch\Scripts\python.exe -m unittest discover -s tests -v
.\.venv-pytorch\Scripts\python.exe experiments/evaluate_temporal.py --run outputs/run-20261006-163717-935432 --run outputs/run-20261006-163723-337973
```

第二条命令复用同一份已保存检测日志，比较即时触发的连续检测片段与时序事件。合成序列只验证规则行为；真实壁炉检测回放尚无独立事件真值，不能由片段数差异推导误报下降比例。
