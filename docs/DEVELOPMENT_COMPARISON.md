# 四段开发素材的初步评价

日期：2026-10-06。目的：用已曝光的四段视频验证评价口径，观察单帧检测与时序确认的误提示/延迟取舍。不是全量测试、内部留出效果或完全独立的外部测试。

## 固定口径与证据

同一份逐帧检测输出分别产生单帧活动状态和时序已确认活动状态；置信度沿用 0.35，模型与时序参数未调整。时序暂缺证据时的确认保持也计入活动状态，不只统计确认瞬间。

人工标签按 fire/smoke 分别评价。连续可见区间以及活动提示使用统一的 ≤1 秒间隔合并口径；场景事件检出要求至少在一帧实际可见标签上存在对应类别活动提示。负标签帧上的活动提示也按同样口径合并为误提示片段。因此“误提示片段”不是逐帧检测次数，也不是原始通知次数。

首次有效提示延迟相对人工可见区间起点，采用帧号/FPS；不是相对真实点火时刻的延迟。已有提示状态持续进入正区间时可产生零延迟，需要结合误提示和画面解释。没有正事件时延迟留空，没有负时长时误提示率留空，不假装是零。

原始输出：`outputs/development-comparison-20261006-202600-029136/`，含固定口径 `protocol.json`、标注快照与 SHA256、评价代码 SHA256、两种方法的结果、模型/运行配置、缓存检测/时序日志 SHA256 和完整报告。

## 本轮观察

| 岩壁负例 `negsVideo1.858.avi` / fire | 8 | 1 | 无正事件 |

| 烟雾正例 `testpos01.817.avi` / smoke | 0 | 0 | 0.750 → 1.833 秒 |

`testneg01.807.avi` 两类均没有活动提示。这四段的三项正类场景事件均有活动提示，但样本数量非常小；不据此报告“100%准确率”。

岩壁误提示仍存在。时序确认减少了部分短暂误检，但也使提示变晚，尤其第一段的烟雾提示。从本轮不能得出“全场景误报率降低”“没有漏检”或“风险等级正确”的结论。需要保留失败案例，再在固定划分下验证。
