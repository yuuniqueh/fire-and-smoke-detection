# 提示等级与声光提醒方案

更新：2026-10-19。

## 本轮已实现

| 内部等级 | 用户看到的提示 | 视觉与动作 |
| --- | --- | --- |
| LOW | 黄色提示 · 请核查 | 黄色浅底、色条、感叹号，提示查看疑似事件证据 |
| MEDIUM | 橙色提示 · 优先核查 | 橙色浅底、色条、感叹号，优先查看最新证据 |
| HIGH | 红色提示 · 立即核查 | 红色浅底、色条、感叹号，突出立即查看画面和核查 |

文字、颜色和符号共同表达优先程度，不单独依赖颜色。三档均为软件的**核查优先程度**，不是消防火灾等级、实际火势或起火概率；模型、规则阈值和等级计算未调整。

“发现疑似火焰 / 烟雾”与“核查优先程度”分别展示。“待核查 / 已知悉 / 疑似误报”属于人工工作流状态，不作为等级名称。

未运行、画面延迟和未知状态用文字明确说明；不显示绿色“安全”。历史结果用灰色卡片，标题写“历史记录 · 不代表当前现场状态”，等级注明“当时提示”。历史结果不重新响铃。旧日志的原始文字不改写，提示列表以新词汇展示。

## 软件声音

现有声音使用本机系统提示音 `QApplication.beep()`，不是持续鸣笛，也不代表外接警报器。

- 设置页新增“试听提示音”，明确要求用户确认系统音量、输出设备和静音状态。
- 橙色 / 红色新事件或升级提示在用户开启声音后可发声，沿用现有证据新鲜度、冷却和去重规则。
- 首页显示声音是否开启或临时静音；支持静音 5 分钟和主动恢复。静音不关闭检测和视觉提示。
- 默认声音设置不变，不因界面改版擅自开启。试听不改变声音开关、静音期限、人工反馈或检测状态。
- 本轮未增加持续铃声、自定义音频、全屏闪烁或外接硬件控制。

## 外部声光设备的取舍

建议本阶段优先完成本机声音、屏幕高亮和人工核查闭环；外部警灯 / 蜂鸣器联动等确定设备与演示场景后再做。

外部设备联动由两部分组成：硬件执行发声和发光，软件根据事件发送触发 / 复位指令并处理结果。具体接法取决于设备提供的网络 API、I/O 或其他协议，不能仅凭一个界面开关就称为已经支持硬件联动。

现有事件通知模型可作为后续适配的输入，但本轮没有添加可执行的硬件输出接口，也不显示虚假的“已连接”或“已启动”状态。后续接入需要核对设备协议、连接状态、触发条件、复位、超时、重复命令及失败反馈，并用真实设备验收。
