# 本地存储管理

2026-10-12：桌面新增“存储管理”页，摄像头默认只保存事件片段。已有历史记录没有在开发验收中清理，实际清理功能只在临时测试目录验收。

## 使用

1. 重新启动 `start_desktop.cmd`，打开“存储管理”。已有设置会补充安全默认值：摄像头事件片段、30 天、5 GiB、自动清理关闭。
2. 点击“扫描占用 / 预览清理”，查看每条记录的大小、保留状态及清理原因。扫描不会删除文件。
3. 对需要长期保留的记录，选中后点击“标记为重要记录”；再次选中可解除保护。
4. 调整天数和容量后重新扫描。先选超过期限的记录，再按最旧优先释放容量；两个条件满足任意一个就可能进入清理计划。
5. 点击“清理预览中的记录”，查看确认说明后执行。删除的是整条运行记录，包括录像、截图、日志、人工反馈，不能在软件内撤销。源视频、模型、数据集、缓存和已导出的 ZIP 不在管理范围。
6. 如需监控时自动清理，主动勾选对应选项。它在监控开始及运行期间检查旧记录，不会在修改选项的一刻立即删除历史文件。普通文件分析也使用容量/期限策略。

“当前查看”和事件回放使用的记录会被本窗口排除。希望清理当前记录时，先关闭回放窗口，点击“结束当前查看”，再重新扫描。这只卸载当前视图，不删除记录。

## 录像方式

摄像头支持三种方式：

| 方式 | 内容 |
| --- | --- |
| 仅事件片段（默认） | 确认事件或提示等级升级时保存前最多 5 秒、后 10 秒的已处理画面；安静时不永久保存录像 |
| 完整处理录像 | 保留所有处理帧，便于调试；不等于完整手机原始录像 |
| 不录像 | 仍保留事件截图、事件/提示、配置、总结和详细日志 |

事件前缓冲只驻留内存，限制 32 MiB、180 个处理帧；起步、低帧率、大画面或处理缺口可能使前段不足 5 秒。相邻触发可合并，长片段按约 60 秒轮转。长事件不会一直录像到解除，仅保存触发附近的画面和后续等级升级片段。

事件模式使用 `clips.json` 和 `clips/clip-N.mp4`、`clips/clip-N.jsonl`。软件按观测时间定位和播放；外部播放器直接播放 MP4 可能变快。回放和 ZIP 导出均兼容完整录像及事件片段。

本地视频文件分析仍默认保存完整处理录像，以保留复核能力。详细逐帧日志本轮继续保留，由容量/期限管理；没有宣称日志已压缩成只有事件。

## 容量与保护边界

- 容量统计管理 `outputs/run-日期-时间`，包括重要、使用中和不可清理记录的可读取文件；不等于整个项目或整个磁盘占用。
- 容量在开始及约每 10 秒检查，是停止/清理阈值，单次检查间隔内可能短暂超过上限。当前运行不会为释放容量而删除自身。
- 未开启自动清理，或保护/活动记录使容量无法释放时，会停止监控并保留当前结果，提示用户清理、提高上限或调整保护。
- 原有摄像头剩余磁盘不足 500 MB 停止保护保留。
- `.active` 标记跨进程的分析运行；`protected.json` 标记重要记录。崩溃后残留的活动标记、没有总结、含陌生文件或目录链接的记录保守跳过，不自动判断可删除。
- 清理前复核目录边界、保护状态、活动状态及文件大小/修改时间签名。预览之后记录变化会被跳过。清理/保护操作使用互斥标记，避免两个清理任务并行。
- 存储策略和录像方式只影响记录，不改模型、时序确认、人工真值或训练。
