# 焰鉴产品框架与操作说明

事件使用流程更新：已接通前后视频回放、提示/事件跳转、处理状态与组合筛选，以及可读报告导出。见 [事件核查与处理](EVENT_REVIEW_GUIDE.md)。这轮只完善产品流程，既有检测与确认规则没有调整。

更新：2026-10-11。当前目标是把本地视频的“分析—解释—提示—复盘”流程做完整，保留可继续改进检测、关联和预测模块的接口。本次没有训练模型，也没有恢复新来源数据的准确率或泛化实验。

## 已接通的流程

```text
本地视频逐帧解码
  → 监测调度（完整检测 / 低负载巡检）
  → 火焰、烟雾检测
  → 同类区域关联与时序确认
  → 视觉指标与等级
  → 检测框覆盖趋势的短期外推
  → 本机界面提示、提示日志、可选提示音
  → 人工知悉 / 疑似误报反馈
  → 事件、证据截图、历史查询与记录导出
```

桌面与命令行共用 `core/pipeline.py`。检测适配器、监测调度、时序关联、指标、趋势和提示各自独立，界面负责展示与显式人工操作。一个视频对应一个新建的分析状态和结果目录，不跨视频累积证据。

默认仍使用原模型、原关联、输入尺寸 640 的逐帧分析。已有的“减少反光误报（候选）”模型组合和“稳定区域（候选）”关联保留为可选方案；新增功能没有证明候选全面优于原方案。既有模型权重、时序阈值与风险评分规则没有因本次界面功能建设而重新训练或调优。

## 启动与查看

1. 双击项目根目录的 `start_desktop.cmd`，或运行 `.\.venv-pytorch\Scripts\python.exe desktop.py`。
2. 点击“壁炉示例”或“打开视频”。在“分析配置”中选择设备、检测方案、事件关联和监测方式；需要时勾选中、高等级本机提示音。
3. 点击“开始分析”。“监测总览”显示画面、事件、视觉指标与当前调度状态；“趋势观察”显示检测框覆盖历史和可用时的外推结果；“提示中心”查看提示并记录人工处理。
4. 分析结束后，可以在“历史分析”载入结果、查看事件与证据截图，或导出记录 ZIP。历史提示不会重播声音，历史趋势显示对应的视频时刻。

运行中点击“停止”会在当前推理返回后保存记录并释放资源。“按原视频速度显示”只影响播放节奏；性能不足时处理变慢，时间仍按源视频帧号/FPS 计算。

## 低负载巡检

| 阶段 | 当前行为 | 目的 |
| --- | --- | --- |
| 完整检测 | 每帧输入尺寸 640 | 保持现有逐帧方式和比较基准 |
| 巡检 | 每秒约 2 次、输入尺寸 416；每 5 秒一次尺寸 960 的巡检，首帧也用 960 | 减少平稳画面的模型调用，同时定期检查弱线索 |
| 异常增强 | 有候选框就立即唤醒；同一帧先以 960 复检，再进入逐帧 960 检测 | 在候选事件附近积累连续观测 |
| 返回巡检 | 增强至少持续 8 秒，并且候选/确认轨迹消失后满足至少 3 秒安静条件 | 避免候选出现、消失时频繁切换 |

低分辨率候选是唤醒信号。同一帧的时序证据只使用增强复检的最终结果，避免把两次推理当成两帧。

未调用检测器的帧仍解码、展示并写入输出视频，日志标记 `observed=false`。这些帧不作为“没有火焰/烟雾”的测量，也不向时序模块补造空检测。界面显示“低负载巡检/本帧未检测”，风险曲线在未观察处留缺口。

这是可选择的计算调度原型。统计的是检测帧数、跳过帧数、模型调用与处理耗时，没有测量电能或电池续航；不能直接宣称节电百分比。巡检间隔内的短暂目标和低分辨率弱目标仍可能被漏过，周期性高分辨率检查不能消除此风险。尺寸 960 也不会恢复原视频不存在的细节。以前固定 640 的结果不能直接用作该模式的准确率结论。

## 趋势外推的含义

趋势模块对已确认事件的平滑检测框并集占画面比例作线性拟合：保留最近 6 秒，至少积累 3 秒和 8 个采样点后，才尝试外推未来 3 秒。显示增长速度、预测覆盖、历史残差形成的范围以及观测曲线。

| 状态 | 界面应如何理解 |
| --- | --- |
| 正在积累观测 | 历史长度或采样点不足，暂不给未来值 |
| 可进行短期外推 | 当前历史通过数值稳定性检查，显示外推曲线 |
| 检测暂缺 | 不把缺失当成面积缩小，暂停外推；较长缺口后重新积累 |
| 观测不稳定 | 当前历史不适合线性拟合，只显示观测与原因 |

外推对象是**检测框覆盖**，不是实际燃烧面积、火灾概率或经过验证的火势蔓延预测。阴影范围来自历史拟合残差，不是有保证的统计置信区间。遮挡、镜头运动、目标距离和检测框抖动都会影响结果。模块不会因为预测增长就自动提高原有风险评分，也不会据此控制消防设备。历史载入展示最后一次保存的事件观察，不表示当前现场状态。

## 分级提示与人工反馈

视觉指标沿用 LOW、MEDIUM、HIGH 三档，提示用语分别为“注意”“核查”“优先核查”。等级由已确认视觉线索、框覆盖、持续观测、增长和检测置信度的既有规则计算，不是消防部门的火灾分级。

事件确认、等级上调、等级回落和事件关闭会生成离散提示，并写入日志。界面和日志可查看所有这些变化；可选本机提示音只用于有新鲜证据的中、高等级确认或升级，遵守事件冷却抑制。等级不变时不会逐帧重复提示。系统声音能否听到仍取决于操作系统声音设置，日志中的声音通道是请求记录。

“已知悉”记录用户看过提示；“标为疑似误报”记录人工判断和可选说明。反馈追加保存，保留原检测与事件结果，不自动把反馈变成训练真值，不在后台训练或更新模型。后续若利用难例，仍需独立复核标注。事件结束、等级回落或用户知悉均不代表现场已安全。

## 保存与兼容

每次分析在 `outputs/run-*` 中保存配置、总结、带标注视频、检测/时序/风险日志、事件与证据截图；新增 `monitoring.jsonl`、`trend.jsonl`、`trend-latest.json`、`alerts.jsonl`，有人工处理时保存 `feedback.jsonl`。参数与监测方式写入本次配置，便于区分不同方式的输出。

界面保留有限长度的画面预览、曲线、事件与提示列表，完整逐帧结果写入文件。旧记录没有趋势、提示或调度字段时仍可读取，显示“未提供”或空列表。记录 ZIP 包括已有的新日志和反馈；不复制模型权重或原视频。配置中仍有原机器路径，正式参赛导出材料需另行核对匿名要求与第三方授权。
