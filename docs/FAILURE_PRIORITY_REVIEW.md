# 当前错误的处理优先级

依据：固定基线开发组 30 段视频的 development-failures.json、完整基线报告，以及既有阈值/时序受控试验。未重新训练、未改变配置或真值。以下计数沿用原冻结标注，2026-10-06 复核。

## 判断

最严重的现象是已标注火焰事件的最终漏报：fire 确认 8/13、漏报 5/13，smoke 确认 9/11、漏报 2/11。这只是小规模开发组现象，不能外推真实部署漏报率。

优先处理困难目标的检测支持不足与定位不可靠，其次检查空间关联/证据累积。不能仅凭“有原始框但没有确认”就把原因全归给时序规则；偶尔一两帧输出也可能来自错误物体。

最后一例需要单独核查：正确目标的漏检/框抖动、错误背景框、空间关联和确认条件可能共同作用，尚未证明纯粹的跟踪算法缺陷。

## 为什么不先整体放宽时序

原配置 fire 检出8/13、误提示片段3；smoke 9/11、误提示片段1。保持模型不变，放宽观察时间/正证据时间/存在比例后，fire 只增加到9/13，误提示增至11；smoke 检出仍9/11，误提示增至7。仅将关联IoU从0.10降至0.05没有检出增益。

这些试验反对简单放宽全局阈值，但不能否定更合适的时序/关联方法。原始误提示片段 fire52、smoke67，经确认分别降至3、1；残余持续错误分类仍需要定位复核与检测器改进。

## 工作顺序

1. 复核上述一处时间区间与图片判断差异；保存版本，不自动改写原冻结评价。
2. 优先比较检测器在可见小火焰、薄烟、遮挡和困难背景上的原始输出及正确定位，再评价完整视频；目标是获得持续的正确证据，而非只增加框数。
3. 对 testpos02.818 单独核对正确目标的连续框/轨迹，决定是否需要改善关联和证据累积；不先对全部视频降低确认要求。
4. 同时保留误提示、检出、定位与延迟护栏。没有受控增益，不采用新模型或新规则。
