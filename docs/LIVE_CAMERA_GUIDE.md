# Windows 实时摄像头监控

2026-10-12：现有桌面产品增加 Windows 摄像头输入。训练、模型选型和 GitHub 同步继续暂停。当前是开发版，尚未制作正式安装包。

同日存储更新：新增“存储管理”，摄像头默认仅保存事件附近片段，支持重要保护、30 天/5 GiB 策略和清理预览。自动清理默认关闭；详见 `STORAGE_GUIDE.md`。

## 使用

1. 双击项目根目录 `start_desktop.cmd`。
2. 顶部输入类型选择“摄像头 / 安卓手机”。普通 USB 摄像头和内置摄像头可直接使用。
3. 安卓手机先使用配套工具连接电脑，例如 DroidCam 手机端和 Windows 客户端，按其说明使用同一 Wi-Fi 或 USB。工具须提供 Windows 摄像头设备，普通视频播放窗口不等于虚拟摄像头。第三方传输模块并非本项目自主开发。
4. 指定摄像头编号，从 0 开始，点击“连接预览”。画面不对时停止，换 1、2 等编号重试。本版不扫描全部设备，也不存储手机地址或连接密码。
5. 预览不加载模型、不检测、不录像。点击“停止”后，再点击“开始监控”。
6. 监控使用当前检测、确认、监测和提示配置；提示中心支持本机提示及人工反馈。相机模式禁用“按原视频速度显示”。
7. 点击“停止”后等待保存，再查看事件、回放或导出 ZIP。断线会结束本次监控，检查连接后再次预览或开始监控，创建新记录；没有自动重连或跨断线累计证据。

Windows 需允许桌面应用访问摄像头。连接失败时检查编号、权限、USB/Wi-Fi，以及是否有其他应用独占摄像头。界面有“手机连接说明”。

第三方工具官方入口：https://droidcam.app/ 。设备支持和费用以工具官方说明为准。本项目没有捆绑、下载或安装该工具。

## 时间、记录与故障

- 实时分析使用电脑收到采集帧的单调时钟，以首个分析帧为零点；不是手机曝光时间或绝对日期时间。推理慢时跳过旧的采集帧，未处理帧不能当作无火无烟。
- 摄像头在独立进程采集，图像队列最多两帧。处理线程取较新的帧，避免在 Python 中积累旧画面。驱动或第三方工具内部仍可能有缓冲，其延迟尚未验证。
- “采集到处理”仅覆盖电脑采集完成到本次处理输出，不包括手机拍摄、编码和网络传输，不能称为手机到界面的完整延迟。
- 默认只保存事件片段，安静时仅在内存缓冲；可选完整处理录像或不录像。完整录像使用 `annotated.mp4` 和 `frame-times.jsonl`，片段使用 `clips.json` 和 `clips/` 的录像/索引。容器为 30 FPS，实际观测并非固定 30 FPS；内置回放按索引定位和实际间隔播放，外部播放器直接播放可能变快。索引缺失、损坏或帧数不符时拒绝按事件时间回放。
- 录像、日志、截图、事件、提示和时间索引随运行保存，ZIP 包含已有片段及索引。没有完整原始手机录像或音频。事件片段按约 60 秒分段；没有完整录像的连续分段轮转。
- 连接超时约 10 秒；连续约 5 秒无有效新画面时中断并报错。超过 1.5 秒未收到处理画面时提示画面可能过时，也可能由推理较慢导致。
- 每 60 个处理帧检查剩余磁盘，不足 500 MB 时停止并保存；记录总量另在开始和约每 10 秒检查。支持期限/容量清理及重要保护；没有全天运行验收或严格逐字节硬配额。
- 断线、停止或磁盘不足是软件结束边界，不表示实际火情结束。结束后顶部明确显示没有实时检测，最后一帧不代表现场当前状态。
